# Architecture

> Generated by codebase analysis on 2026-05-22

## Overview

Think to Build is an event application for an AI image-matching competition. The application runtime is split into:

- An Express server that serves static browser pages, exposes JSON and multipart APIs, owns authentication, persists event/team state in MongoDB, and broadcasts live updates with Socket.IO.
- A FastAPI CLIP service that loads `openai/clip-vit-base-patch32` and scores participant image uploads against an admin-supplied reference image.
- Static HTML, CSS, and browser JavaScript for public landing, registration, participant dashboard, admin, team list, and judge leaderboard flows.

The repository root also contains GSD workflow docs, scripts, adapters, and skills. Those files support development workflow but are not part of the event runtime.

## Components

### Express Host

- **Purpose:** Starts HTTP and Socket.IO servers, configures middleware and static file serving, exposes page routes, and connects to MongoDB asynchronously.
- **Location:** `backend/server.js`
- **Dependencies:** Express, Mongoose, Socket.IO, Helmet, Compression, CORS, filesystem-backed upload directories.
- **Dependents:** Root `npm start`, browser page routes, API router.

### API Router

- **Purpose:** Implements registration, team login, admin/judge login, event control, image upload/scoring, team list, leaderboard scoring, and reference image upload.
- **Location:** `backend/routes/api.js`
- **Dependencies:** JWT, Multer, rate limiting, Mongoose models, CLIP service adapter, Socket.IO instance stored on the Express app.
- **Dependents:** Browser scripts in `backend/public`, manual integration flow in `backend/test-score.js`.

### Persistence Models

- **Purpose:** Store team registration, upload attempts, image scores, Round 2 rubric scores, opt-out/disqualification state, and the single event start/stop state document.
- **Location:** `backend/models/Team.js`, `backend/models/EventState.js`
- **Dependencies:** Mongoose.
- **Dependents:** API router.

### CLIP Adapter

- **Purpose:** Queues Node-to-Python image comparison calls with a two-request concurrency limit and returns a numeric fallback score when the CLIP service fails.
- **Location:** `backend/services/clip.js`
- **Dependencies:** Axios, FormData, local uploaded files, `CLIP_SERVICE_URL`.
- **Dependents:** `/api/upload-images`.

### CLIP Scoring Service

- **Purpose:** Accepts two image files and returns a scaled CLIP cosine similarity score from 0 to 100.
- **Location:** `clip_service/app.py`
- **Dependencies:** FastAPI, Transformers, PyTorch, Pillow, Python multipart parsing.
- **Dependents:** Node CLIP adapter.

### Browser UI

- **Purpose:** Implements public marketing/navigation, registration, participant upload flow, admin control panel, public team list, and judge scoring table.
- **Location:** `backend/public`
- **Dependencies:** Server-served API routes, Socket.IO client, Google Fonts, CDN Three.js, CDN html2pdf.
- **Dependents:** Event participants, admins, and judges.

### Dormant AI Service

- **Purpose:** Contains Gemini/Pollinations generation and Gemini image evaluation helpers from an older or future image-generation path.
- **Location:** `backend/services/ai.js`
- **Dependencies:** Google GenAI, Axios, filesystem, Gemini key variables.
- **Dependents:** No current runtime route imports it.

## Data Flow

1. A participant registers from `backend/public/RegistrationFolder/register.js`. The API creates a `Team` record and returns a team ID plus a team JWT.
2. Participant login from `backend/public/js/team.js` resolves the `Team` by team ID and stores the returned JWT in browser `localStorage`.
3. An admin signs in, uploads `uploads/reference/reference.jpg`, and starts the event. Event state is persisted in `EventState`.
4. A participant uploads up to three images through `/api/upload-images`. Multer stores files under `backend/uploads/generated`.
5. The API validates event/team state, sends each accepted image and the reference file to the Python CLIP service, records image scores, keeps the best score as `round1_score`, and increments upload attempts.
6. Socket.IO emits event and leaderboard updates so dashboards refresh state without polling every action.
7. A judge loads all teams through `/api/admin/teams`, enters Round 2 rubric values, and saves the computed Round 2 score through `/api/admin/score`.

## Conventions

- **Structure:** Runtime code is grouped by `backend` and `clip_service`; the frontend is a static multi-page app inside `backend/public`.
- **API style:** Express router handlers return JSON objects and use route-local validation with `try/catch`.
- **Realtime style:** Mutating event, upload, opt-out, and score actions emit Socket.IO events such as `event_started`, `event_stopped`, and `leaderboard_update`.
- **State:** Server state lives in MongoDB and filesystem uploads; browser session tokens live in `localStorage`.
- **Testing:** The repo has manual scoring scripts but no configured automated backend test suite.
